# ローカルモデルの検出と登録

## 解析画面からモデルを追加する

「新しい解析」のモデル欄にある「モデルを追加」からModel Managerを開く。登録がないときは内蔵の数値検証モデルだけが選択できる。実モデルの重みはGitやセットアップに含めない。

Model Managerでは次のいずれかで保存場所を指定する。

- 「モデルフォルダーの絶対パス」へ直接入力する。Windowsの「パスのコピー」で付く引用符も受け付ける。
- 「フォルダーを選択」でバックエンドOS上のフォルダーを開き、「このフォルダーを使用」を選ぶ。
- 検出候補の「この場所を指定」を選ぶ。

指定するのはconfig.json・Tokenizer・safetensorsを含むフォルダー。ファイルをブラウザへアップロードする操作は不要。「内容を確認」で構成と不足ファイルを確認し、「登録して解析に使う」で登録する。登録後は解析画面へ戻り、追加したモデルが選択される。入力途中のプロンプト・実験条件は維持する。

登録情報はバックエンドのカタログへ永続保存する。最後に選んだモデルIDはブラウザに保存する。WindowsとWSLのカタログ・モデルパスはそれぞれ独立し、画面に対象OSを表示する。フォルダー選択は同じテーマのWebダイアログで、ホーム・ドライブ／ルート・探索先への移動、絶対パス入力、子フォルダー名の絞り込みを提供する。

## 自動検出

Model Managerを開くと、以下を探索する。「再検出」で繰り返せる。

1. リポジトリの `.tools/models/` と `models/`。
2. Hugging Faceキャッシュ。`HF_HUB_CACHE`、`HUGGINGFACE_HUB_CACHE`、`HF_HOME/hub`、`XDG_CACHE_HOME/huggingface/hub`、既定の `~/.cache/huggingface/hub` の優先順で場所を決める。環境変数参照・ホームの省略表記も展開する。
3. 「探索する場所」に追加した任意の絶対パス。最大16件をカタログのsettings/model_searchへ保存する。

各探索先から4階層、全探索で最大2,000フォルダー・200候補。15秒を目安にディレクトリ境界で区切る。OSのファイル操作自体を即時中断する保証はない。リンク・ジャンクションのディレクトリは再帰せず、Hugging Faceの重みファイルのリンクは利用できる。同じ実パスは重複表示しない。別snapshotや別コピーは独立した候補として扱う。

検出はGPUジョブとは別の単一スレッドで実行する。途中の候補・確認件数を取得でき、中止時は見つかった候補を残す。上限到達・読み取れない場所を表示する。フォルダー選択の1階層表示は最大300件で、上限時は直接パスで移動できる。

検出時は小さな設定ファイルとファイルの存在・容量だけを確認し、モデル重みの読込・ハッシュ計算・ダウンロードは行わない。対応構造、量子化、分割重みの不足、Tokenizerの不足を候補の理由として表示する。

## 登録と保存場所の変更

登録時はTokenizerをローカル限定・カスタムコード無効で実際に読み、safetensorsヘッダーとファイル長を確認し、従来どおり重み・設定・Tokenizerのfingerprintを計算する。**検出や登録は内部活性値の数値品質の検証とは異なる。** 実モデルでの取得品質は解析時の整合性チェックとモデル別の検証記録で判断する。

対応範囲は[モデルと取得範囲](model-support.md)を参照。新しい形式・量子化・別アーキテクチャへの対応を、この機能で追加したわけではない。

登録済みモデルの必要ファイルが消失・不足した場合は、選択欄で利用不可を示し、解析開始を無効化する。Model Managerの「保存場所を再指定」で移動先を指定すると、全fingerprintが一致する場合だけ既存の登録ID・検証情報を維持してパスを更新する。異なる重み・Tokenizerは新しいモデルとして登録する。

## API

- `GET /api/models/discover-local`: OS、探索先、追加した探索先。
- `PUT /api/models/search-paths`: 追加した探索先の保存。
- `POST /api/models/discovery`: 検出開始。実行中なら同じ検出を返す。
- `GET /api/models/discovery/{id}` / `POST .../{id}/cancel`: 状態・中止。
- `POST /api/models/inspect`: 重みを読まずに構成を確認。
- `GET /api/models/folders?path=...`: バックエンド上の1階層のフォルダー一覧。
- `POST /api/models/register`: 内容の検証・fingerprint照合・登録。
- `POST /api/models/{id}/relocate`: 同じ重み・Tokenizerの保存場所を更新。

既存のHost・Origin・セッション・操作トークンの制限を共通に適用する。探索ジョブはメモリ内で直近8件まで保持し、再起動後は再検出する。

## 今回の検証（2026-10-21）

Windowsで探索の上限・中止・重複・不足ファイル・非対応構造・権限エラー、探索先／登録の永続化、移動後の同一性をテストした。ブラウザではランダム重みの小型GPT-2構成でフォルダー選択→登録→モデル選択→実解析を確認し、入力中プロンプトの維持、390〜1440pxの表示、Esc終了・フォーカス復帰も確認した。今回のUI変更について、WSLでの再実測や新しい事前学習済みモデルの品質検証は行っていない。
